# Five-task learning study

Run from the folder containing settings.py with your oTree virtual environment activated. Install requirements with `python -m pip install -r requirements.txt` and launch `otree devserver`. Choose **Five-task study — random assignment** for a random pair. In **Testing — all 20 task orders**, participant 1 receives Two urns followed by General knowledge. This configuration fixes task pairs only. Run `otree test check_orders 20 --export` to exercise every ordered pair.

## Tasks and content

- **Two urns.** Each round uses its own pair of ten-ball compositions (editable in tasks/urns.py). Left is red-majority, right blue-majority. The source is independently uniform each round. Its ball is sampled once when the session is created. The labelled illustrations match the counts. The participant reports a probability from 0 to 100%. With equal priors the Bayesian posterior is L/(L+R), where L and R are the probabilities of the observed colour in the left and right urn. Accuracy equals 2 × (1 − (reported probability − posterior)²), rounded to hundredths. E.g. for a red draw with 7/10 and 3/10 red, a 50% response earns 1.92 points. Own-round feedback shows the posterior and score.
- **General knowledge.** Fill tasks/data/knowledge.csv with ten questions, one per row. Keep IDs GK01 through GK10. Fill question, four answer options A–D and key (A, B, C or D) for each item. Blank rows explicitly use a practice input with an instructed answer so the pilot and payment flow run. Such rows are flagged by practice_item in the export. Populated rows show the real question. Start a fresh session after editing the bank.
- **Colours, Shapes, Animals.** Three simple click placeholders use the option lists in their respective modules.
- **Example panels.** No pre-experiment histories are included. High urn rounds show text slots for the example's separate compositions, draw and chosen urn. High knowledge rounds show slots for the example participant's answer and total correct out of ten. Neither panel labels any example response correct or incorrect. The urn page also asks for usefulness (1–5; code 0 means cannot assess a pending example). Low rounds skip this question entirely. To supply real data later, update the context and templates for UrnDecision and KnowledgeDecision using the round-matched responses from the selected pre-experiment participant. The figures on the current urn page illustrate the current participant's own case.

## Experiment flow

settings.py registers assignment then tasks. assignment/__init__.py draws the two distinct tasks in order and independently assigns Exogenous/Endogenous 50/50 and Low/High/Choice 25/50/25. Task 1 starts with instructions, five MPL rows at 0–4 points, treatment reveal and initial own-performance forecasts for rounds 5 and 10. For task 2 only Choice repeats the MPL, with a fresh draw. Only Exogenous sees the average-performer sentence. In Choice, accepting the selected price gives High for that task and incurs the price once. Declining gives Low. Fixed High and Low retain their levels. Give feedback after each response and elicit an updated round-10 forecast after round 5 feedback.

## Beliefs and payment

An urn decision estimates the source probability. A separate performance forecast predicts the participant's own accuracy score in round 5 or 10, on the same 0–2 scale. Other performance forecasts are percentages for answering the indicated round correctly. After both tasks, draw one of ten decisions and one of three forecasts independently per task. Pay the selected urn score directly or 2 points for a correct selected non-urn answer. The forecast bonus equals 2 × (1 − normalized error²). For urns, normalized error is (forecast − actual points)/2. For the other tasks it is forecast/100 − correctness. Add the 4-point endowment and deduct any binding MPL cost once. The two task payoffs are credited to oTree, recorded on overall rounds 10 and 20. Payment constants and scoring functions live in payment_rules.py.

## Code and export

tasks/__init__.py contains the Player fields, page_sequence, treatment checks, specialized decision pages and settle_task. The templates are alongside it. UrnDiagram.html draws the labelled urns. In tasks.csv inspect task, position and task_round; for urns inspect left_red, right_red, source_left, ball, probability_left, posterior (0–1), usefulness and score. For knowledge inspect item_id, practice_item, knowledge_answer, answer_key and correct. initial_r5 and initial_r10 are recorded on task round 1; updated_r10 on task round 5. Their units depend on task. Final records contain paid_round, paid_belief, paid_forecast, forecast_target_score, decision_bonus, belief_bonus, payment_cost and payoff.
